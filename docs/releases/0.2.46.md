# v0.2.46 — shared-subscription delivery hotfix

Replaces **v0.2.41–v0.2.45**, which must not be deployed because of known
shared-subscription delivery bugs.

## Fixed

- An online shared group no longer also accumulates messages in its offline
  members' Redis queues. When every member is offline, routing selects one
  exact owner/client for the group across the cluster.
- An edge reached for an ordinary subscription, another shared group or an
  offline route cannot independently deliver a second shared copy. The source
  selects each shared group's node once and carries the authorized filters
  through local delivery and the gRPC dataplane.
- Disconnected persistent clients and rehydration ghosts are excluded from
  live shared elections. Same-edge reconnects recover messages queued
  directly in Redis while offline.
- A full offline queue no longer causes up to 65,535 Redis network round
  trips per enqueue. Packet-ID search runs on Redis under the existing WATCH
  protection, and waiting for the per-client enqueue lock respects deadlines.

## Compatibility and rollout

- This release keeps the existing **legacy numeric IFM storage format**. It
  does not include or activate the pending directional IFM migration.
- No new required configuration flags, Redis reset or full broker shutdown
  are required. Keep Redis resources sufficient for any existing backlog.
- Update core and edge images in separate rollouts, core first, then edges
  one at a time with sufficient spare capacity for reconnects. Shared routing
  reads remain local; no new core RPC is required.
- New protobuf fields are additive. Messages from old peers remain readable,
  but old senders/receivers cannot enforce the new shared-routing metadata.
  The fix is fully effective only after **all traffic-serving edges** have
  been upgraded. Mixed-version rollout is not a duplicate-free guarantee.
- The update does not delete previously queued messages. Do not remove IFM
  hashes blindly: backlog recovery is a separate operation.

## Limits

MQTT QoS1 retransmissions remain valid protocol behavior. This fix removes
systematic extra shared deliveries; it does not add durable retries for
inter-edge forwarding failures or exactly-once delivery through Redpanda.
Existing routing-cache convergence and node-failure limitations still apply.

The release is validated with unit/race tests, Redis 7 storage tests and real
core/edge cluster regressions covering mixed ordinary/shared routes, multiple
shared groups, QoS0/1/2 publishers, online/offline members and reconnects.
