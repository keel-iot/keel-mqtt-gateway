# 0.3.5 — Helm connection rebalancing

- Expose `core.rebalance` settings in Helm: enabled, interval, dryRun,
  imbalanceThreshold, maxEvictionsPerNode, evictStagger and excludeClientIDs.
- Run scheduled rebalancing only on the Raft leader; stop issuing scheduled
  disconnections after leadership loss, checking before each eviction.
- Keep automatic rebalancing disabled by default, with the existing 10-minute
  interval, 20% imbalance threshold, 50-client cap per edge and 200ms stagger.

Use matching chart and image 0.3.5. See the chart README for an enabled example.
Clients are disconnected gradually and must reconnect through the external
load balancer; the destination is not assigned by Keel. An eviction RPC already
in flight can complete after leadership changes. Manual API passes are not
serialized with the scheduler.

Includes the Redis primary bootstrap correction from 0.3.4.

Validation: main Go suite, lifecycle race tests, `go vet ./...`, Helm lint,
and default/enabled chart rendering. Enabled output checked for valid YAML,
shell syntax and configured rebalance flags. No new live cluster load test.
