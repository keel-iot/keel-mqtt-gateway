# 0.3.6 — Fair local shared delivery

Shared subscribers on the same edge now receive initial delivery attempts in
round-robin order instead of relying on Go map iteration. This prevents a
single bridge from receiving a disproportionate share of local deliveries
while other members of the same shared filter have capacity.

- Keep an atomic cursor per indexed shared group/filter, shared by matching
  wildcard topics and concurrent publishers.
- Apply selection after Keel removes disconnected members; subscription and
  routing queries do not advance the cursor.
- Retain safe pre-acceptance fallback, subscription property merging, and
  explicit hook selections. Do not retry ambiguous delivery outcomes.
- Release cursor state when the last member unsubscribes.

The behavior is automatic and needs no new Helm settings. Use matching chart
and image 0.3.6. Includes the Redis bootstrap and leader-only scheduled
connection rebalancing changes from 0.3.4 and 0.3.5.

Fairness is local, by message count, with a stable candidate set. This release
does not redistribute bridge TCP connections, increase inflight limits, or add
cross-edge saturation fallback. Existing remote routing from an edge without
local shared members remains available. Existing backlogs may take time to
drain; this change does not guarantee uniform traffic across different edges.

Validation: main and nested MQTT Go suites; race tests for shared selection,
membership changes and fallback; Go build/vet; Helm lint and rendering. No
production deployment or live Kimera load test was performed.
