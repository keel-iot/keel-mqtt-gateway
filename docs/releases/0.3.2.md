# v0.3.2 — Scoped transitive dependency updates

Updates support and Docker test dependencies while preserving the selected
Olric, Raft and memberlist dependency graph from [v0.3.1](0.3.1.md).

## Changes

- grpc-gateway 2.30.0 to 2.31.0 and oklog/run 1.1.0 to 1.2.0.
- Updated Docker connections, Moby API/client/archive, user/userns, gopsutil,
  purego and properties dependencies, including their required supporting
  modules. No application-code adaptation was needed.
- All 118 selected module versions reachable from Olric, Raft and memberlist
  requirements remain identical to v0.3.1, including shared metrics, logging,
  DNS, consistent hashing, bitset, btree and Prometheus dependencies.
- grpc-gateway stays at 2.31.0 because 2.33.0 would update shared x/tools,
  x/mod and x/telemetry modules. franz-go remains at the current 1.22.2 release.

## Validation

- Go build, vet and complete default test suite.
- Go vulnerability scan: zero affected vulnerabilities and zero affected
  imported packages. The existing unused OpenPGP module-only advisory remains.
- Compilation of the tagged cluster test suite.
- Real Testcontainers/Docker smoke check: dedicated network with container
  alias, container startup, mapped ports, archive file copy, exec and logs,
  Redis 7.4.12 PING/SET/GET, and container/network cleanup.
- Comparison of all 118 protected selected module versions after final
  dependency resolution; no protected version changed.
- Helm lint and rendering with and without Redis authentication.

See the [maintenance review](../maintenance/transitive-updates-2026-10-27.md)
for individual versions and the scope of runtime validation.

## Rollout

- Chart version, application version and default gateway image are `0.3.2`.
- No Redis key-schema, PVC or application configuration migration is required.
  Existing resource and storage settings should be retained.
- Redis remains at 7.4.12 Alpine, as in v0.3.1. The Redis read optimizations
  and configurable backlog from v0.3.0 are included.
- Maintain the Raft majority during core upgrades and verify each local Redis
  replica is connected and synchronized before advancing. Pod readiness alone
  does not establish replica synchronization. Existing asynchronous replication
  and failover limitations continue to apply.
- The backlog compatibility default remains `1mb`; use
  `core.redis.replBacklogSize: "128mb"` explicitly where required, with memory
  headroom.
