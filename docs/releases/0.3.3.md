# v0.3.3 — MQTT memory, shared routing and persistence improvements

This release combines the validated allocation/persistence work with the
dependency and coordinated shared-routing changes already shipped in v0.3.2.

## Changes

- Allocate per-client outbound queue storage lazily while preserving the
  configured queue capacity.
- Reduce shared routing snapshots and defer construction of fallback plans
  until a selected consumer fails before acceptance. Keep v0.3.2's exact
  shared-filter forwarding decisions across nodes.
- Remove repeated inflight serialization and separate marker GET requests
  from the stable Redis mutation path; keep atomic schema fences.
- Add `REDIS_IFM_SCHEMA=auto|1|2` and Helm `core.redis.ifmSchema`.
  Auto remains the default. Explicit modes validate existing storage and
  never activate a migration.
- Skip daily output-byte quota accounting when no internal output connectors
  are configured. MQTT byte/message metrics remain active; configured
  connectors keep the existing quota behavior.
- Wait for temporarily missing gossip addresses before forwarding to a
  newly routed edge, within the existing end-to-end deadline. Never retry an
  ambiguously accepted RPC.
- Prevent duplicate ordinary offline enqueue by letting Keel's distributed
  dispatcher own already-offline deliveries in Redis-backed clusters.
  Preserve ordinary standalone Mochi offline behavior.
- Include selective Mochi correctness/race fixes, packet-ID collision
  avoidance, per-client expiry cleanup, offline inventory improvements and
  Redis-only primary health/failover regression coverage.

## Rollout

Use the chart and image version 0.3.3 together. Keep `core.redis.ifmSchema:
"auto"` and the existing Redis marker during this upgrade. The upgrade does
not activate schema 2 and does not delete existing inflight records.

Schema activation is a separate operator action after all writers are
compatible. See [schema operations](../architecture/REDIS_IFM_SCHEMA_MIGRATION.md).
Pinned schema 1/2 rejects mismatched storage instead of silently following a
transition. Preserve any existing admission/rollback restrictions.

There is no change to Redis asynchronous replication guarantees. Unknown
addresses that do not converge before the forwarding deadline still fail.
The offline fix removes the reproduced double-enqueue path, not MQTT QoS 1's
general at-least-once retransmission semantics.

## Evidence and limits

- [Full pre-integration benchmark campaign](../testing/KEEL_PERFORMANCE_2026-10-30.md):
  39 trials, 5,616,000 active messages delivered, no missing/duplicate active
  messages. CPU improvements are exploratory measurements, not a production
  capacity guarantee. One idle connection rejection was retained in the
  report despite a clean repeat.
- [Shared allocation changes](../testing/SHARED_ROUTING_OPTIMIZATIONS_2026-10-30.md).
- [Join fix](../testing/JOIN_ROUTING_CONVERGENCE_2026-10-30.md).
- [Offline duplicate root cause and regression](../testing/OFFLINE_DUPLICATE_ROOT_CAUSE_2026-10-30.md).

The published benchmark image predates integration with v0.3.2's dependency
and exact shared-filter changes. Final release integration receives fresh
unit/race/cluster validation; its performance is not claimed to be an identical
rerun of that benchmark campaign.
